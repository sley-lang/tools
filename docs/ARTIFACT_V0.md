# Native program artifacts

## Fixed program profile v0

This is a bounded transfer profile for Release Readiness and Resource Admission, not a general Sley repository exchange. `sley-tools artifact export --project P --output FILE` reads the verified accepted head and writes one JSON file with the exact stored SCB1 bytes and object identities for 20 or 22 program entities respectively. It excludes the genesis namespace, transaction receipts, policy root, principal grant, workspace configuration, and local paths. The exporter first runs external assertions against the accepted native program. It refuses to overwrite an output file.

The repository has checked-in instances under `programs/release-readiness/` and `programs/resource-admission/`. Each `program.json` records the SHA-256 digest and the source root and entrypoint identities. The manifest's structure is defined by `schemas/program-v0.schema.json`; `scripts/validate_program_manifest.py` also checks its referenced file, digest, and native identity fields.

After a native edit, use `sley-tools artifact export --project PROJECT --output PROJECT/artifact/edited-native-program.json --bind-manifest` to create a new package and bind it to that project's `program.json`. The flag only accepts a new file directly inside the project's real `artifact/` directory; it creates the directory if needed, refuses an existing file, and replaces the manifest after the verified artifact is durable. It records the relative path, checksum, portable status, and the already accepted root and entrypoint identities. An ordinary export without the flag leaves the manifest unchanged. The [bound export probe](../evidence/catalog/bound-artifact-v2.json) edits both catalog programs, validates each resulting manifest, and imports and executes each package in a fresh workspace. A failed metadata update removes its newly written artifact; a process crash between the two file writes can still leave an unbound artifact that must be inspected before retrying.

`sley-tools artifact import FILE NEW_PROJECT --core CORE` accepts a regular file up to 1 MiB and refuses an existing project directory. The importer strictly parses the artifact, rejects duplicate or unknown JSON fields, checks object ordering and the selected program's exact entity inventory, decodes each object with the selected core's canonical codec, and verifies every object identity and profile constant. It derives new entity identities for a new workspace and principal, remaps the internal Sley graph references, and submits the resulting candidate through the public core create, validate, and commit path. The core validates the new graph. The tools then execute external assertions against the imported accepted root. The imported project keeps an exact copy of the source artifact and its SHA-256 digest in its manifest.

The source state root in the file is provenance metadata declared by the exporter. An unrelated importer can verify object digests and destination behavior, but the file alone does not prove that the claimed source root was ever accepted: no signed source receipt is carried. The destination root and entity IDs differ because their authority context differs. The promise is equal typed behavior for the supported inputs, not identical whole-repository identity. The Release Readiness probe compares 60 source and destination outputs; the Resource Admission probe compares 49 exact signed cases across two imports and both SDKs. Both reject tampered objects.

This v0 profile supports the six entity kinds used by both programs. Release Readiness has one record type, one function, four parameters, one block, eleven operations, and two `UInt32` constants. Resource Admission has one record type, one function, four parameters, one block, fourteen operations, and one signed zero constant. The Resource record has five Boolean and two signed 64 bit fields. The importer rejects other graph shapes and cannot transfer arbitrary Sley programs. Native core test admission remains unavailable on the pinned standalone Sley 2.1.1 release; external assertions are reported separately. An imported project records the input file as `imported_source_artifact`; its rebased accepted root has no current artifact binding until it is exported. Export again to package the new accepted root.

## Authored graph profile v1

`sley-tools.native-graph-artifact.v1` transfers one accepted `graph_v0` project. Export runs its external cases, checks the accepted root, and records the exact stored SCB1 objects and object IDs for its function, optional result record, parameters, blocks, constants, and operations. It also carries the bound recipe and case bytes with SHA-256 digests, the named constant IDs, result field identities, core commit, schema epoch, and declared source root. The 8 MiB file limit includes JSON encoding; recipes and cases retain their 64 KiB and 1 MiB limits. Workspace authority, policy, transaction receipts, and local configuration are excluded.

Use the same `artifact export` and `artifact import` commands as v0. `--bind-manifest` writes a current artifact binding in the source project's `program.json`; an ordinary export leaves the manifest alone. Import requires a new destination. It decodes and verifies every native object's stored bytes, ID, kind, unique order, and absence of authority metadata. It then constructs the bound recipe in the destination's fresh identity context, maps every function, result type, parameter, block, constant, and operation to its source counterpart, and compares **every native body** after identity remapping. A differing recipe or object is rejected. The candidate committed through the selected core is rebuilt from those verified source bodies with destination identities, then all bundled cases run against the accepted destination root. The copied source artifact is recorded as `imported_source_artifact`; the new root can be edited and exported again. Both artifact contracts record the core commit they were exported for. Import accepts the pinned Sley 2.1.1 commit and the earlier Sley 2.0.1 commit, which shares its schema epoch and object encodings, so artifacts exported by RC5 can be imported onto 2.1.1; the imported program is bound to the selected core. Any other commit is refused.

The [graph transfer probe](../evidence/graph-builder/portable-artifact-v4.json) replays a branching graph, a primitive-result graph, and a checked reducer. It edits the Data Pipe selector's native predicate, exports and imports that graph, runs it through the unchanged JSON Lines host command, then edits and re-exports the imported graph. A changed recipe with a recomputed digest and a corrupted native object are rejected. This profile covers only the bounded `graph_v0` authoring shape. The declared source root is provenance metadata, not a signed proof of source acceptance; the destination's own core validation and external cases are separate evidence. Native core test admission remains pending.
